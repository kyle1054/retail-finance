Adding a real transport

Everything above the transport already works: the recipient rules, the always-BCC merge, the dry-run valve, and the two features that send (the test above, and the receipt-chase button on a card). Only delivery is missing, and it is one function — _deliver(message) in northwind/services/mailer.py, which receives the finished message (from, to, cc, bcc, subject, html, text, reply_to) and raises MailError if it cannot deliver. Point it at whichever provider the deployment has, and add that provider’s credentials to missing_config() so this page keeps telling the truth about what is still unset.

Sending statements through a third party means staff names and balances transit someone else’s system, so a transport inside the company’s own mail tenant is worth the extra setup where one is available.
